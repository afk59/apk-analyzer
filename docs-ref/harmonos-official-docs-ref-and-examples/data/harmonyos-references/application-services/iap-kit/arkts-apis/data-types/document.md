# Data Types

#### InAppPurchaseData

Purchase data model, which supports consumables and non-consumables.

| 
Name

 | 

Mandatory

 | 

Type

 | 

Description

 |
| :-- | :-- | :-- | :-- |
| 

applicationId

 | 

Yes

 | 

number

 | 

App ID.

 |
| 

applicationIdString

 | 

Yes

 | 

string

 | 

App ID in character string format.

 |
| 

autoRenewing

 | 

Yes

 | 

boolean

 | 

For consumables or non-consumables, the value is always **false**.

 |
| 

orderId

 | 

Yes

 | 

string

 | 

Order ID, which uniquely identifies a receipt to be charged. It is generated by the IAP server when an order is created or a subscription is renewed.

Each receipt matches a unique order ID.

 |
| 

kind

 | 

Yes

 | 

number

 | 

Product type. The options are as follows:

-   **0**: consumable
-   **1**: non-consumable

 |
| 

packageName

 | 

No

 | 

string

 | 

App package name.

 |
| 

productId

 | 

Yes

 | 

string

 | 

Product ID.

NOTE:

After a successful verification of the signature in the payment result, it is a must to check the consistency of this parameter value between IAP Kit and your app.

 |
| 

productName

 | 

No

 | 

string

 | 

Product name.

 |
| 

purchaseTime

 | 

No

 | 

number

 | 

Time when a product is purchased. The value is a UTC timestamp, in milliseconds.

If the purchase is not complete, this parameter is left empty.

 |
| 

purchaseTimeMillis

 | 

No

 | 

number

 | 

A parameter that has the same meaning as **purchaseTime** and used by APIs of earlier versions. If your app has the latest version integrated, just ignore this parameter.

 |
| 

purchaseState

 | 

Yes

 | 

number

 | 

Purchase status. The options are as follows:

-   **\-1**: initialized

-   **0**: purchased
-   **1**: canceled
-   **2**: refunded
-   **3**: pending

 |
| 

developerPayload

 | 

No

 | 

string

 | 

Information stored on the merchant side, which an app passes when calling the payment API.

 |
| 

developerChallenge

 | 

No

 | 

string

 | 

Challenge defined when an app initiates a consumption request, which uniquely identifies the consumption request.

 |
| 

consumptionState

 | 

No

 | 

number

 | 

Consumption status. The options are as follows:

-   **0**: not consumed
-   **1**: consumed

 |
| 

confirmed

 | 

No

 | 

number

 | 

Acknowledgement status. The options are as follows:

-   **0**: not acknowledged
-   **1**: acknowledged
-   If this parameter is left empty, no acknowledgement is required.

NOTE:

This parameter is used only for compatibility with earlier versions. If your app has the latest version integrated, just ignore this parameter.

 |
| 

purchaseToken

 | 

Yes

 | 

string

 | 

Purchase token, which uniquely identifies the mapping between a product and a user. It is generated by the IAP server when a payment is complete.

NOTE:

-   Currently, the value contains 92 characters and its length may be expanded. If the value needs to be stored, you are advised to reserve 128 characters.
-   For security purposes, you are advised to encrypt the purchase token before storing it.

 |
| 

purchaseType

 | 

No

 | 

number

 | 

Purchase type.

-   **0**: sandbox environment (currently unsupported)
-   **1**: promotional activity (currently unsupported)

This parameter is not returned during formal purchase.

 |
| 

currency

 | 

No

 | 

string

 | 

Currency. For example, CNY.

NOTE:

After a successful verification of the signature in the payment result, it is a must to check the consistency of this parameter value between IAP Kit and your app.

 |
| 

price

 | 

No

 | 

number

 | 

Value after the actual price of a product is multiplied by 100. The actual price is accurate to two decimal places. For example, if the value of this parameter is **501**, the actual product price is 5.01.

NOTE:

After a successful verification of the signature in the payment result, it is a must to check the consistency of this parameter value between IAP Kit and your app.

 |
| 

country

 | 

No

 | 

string

 | 

Country or region code, which is used to identify a country or region. The value must comply with the [ISO 3166](https://www.iso.org/iso-3166-country-codes.html) standard.

 |
| 

payType

 | 

No

 | 

string

 | 

Payment method. For details about its values, please refer to [payType](#section29304511489).

 |
| 

payOrderId

 | 

No

 | 

string

 | 

Order ID, which is generated after a user successfully makes a payment.

 |

-   **2**: auto-renewable subscription
-   **3**: non-renewable subscription

 |
| 

quantity

 | 

No

 | 

number

 | 

Quantity of the purchased consumables or non-renewable subscriptions.

-   The **quantity** parameter applies to one product type only. It does not support a mix of different product types.
-   The maximum quantity is **10**.

CAUTION:

If the **quantity** parameter is used to support bulk purchases of products, your app needs to verify that the ordered quantity matches the final delivered quantity to prevent under-deliveries or over-deliveries.

**Atomic service API**: This API can be used in atomic services since API version 5.0.3(15).

**Start version**: 5.0.3(15)

 |

 |

durationTypeCode

 | 

Yes

 | 

string

 | 

Type of a subscription cycle.

-   **0**: normal
-   **1**: extended

 | 

No

 | 

object\[\]

 | 

List of recent active subscription statuses ([SubscriptionStatus](#section1834146183116)) within a subscription group, sorted in ascending order by the time of subscription switching.
