# Referencing and Managing a Shared Package

You can reference a third-party HAR, which is a shared package in effect, from a repository, a local folder, or a local HAR or HSP file.

-   To reference a HAR from an ohpm repository, first set the repository information. You can use the default repository (which is the central repository for OpenHarmony third-party libraries), or select another repository by running the following command from the **Terminal** pane on DevEco Studio. (Before running the command, ensure that [ohpm has been added to environment variables](../../../../coding-and-debugging/appendix/setting-up-the-proxy/document.md#en-us_topic_0000001056725590_li1012418311835). A DevEco Studio restart is required if the environment variable is added for the first time.)
    
    ohpm config set registry your\_registry1,your\_registry2
    
    Note: You can configure multiple repository addresses, separated by commas (,).
    
    Use either of the following methods to add the dependency on the shared package:
    
    -   Method 1: Choose **Tools** > **OHPM Index** from the menu bar to access the OpenHarmony open-source central repository built in DevEco Studio, and select the required third-party package. For details, see [Using OHPM Index to Manage Third-Party Packages](#section1579838153916).
        
        ![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/4c/v3/ppwtQghWSxewaarjCzJOrQ/note_3.0-en-us.png?HW-CC-KV=V1&amp;HW-CC-Date=20260410T062136Z&amp;HW-CC-Expire=86400&amp;HW-CC-Sign=32702212E9EAA576C26D0C7CA7EC4FED9A74B803FFAFD33AD74FD0F82CDE9020)
        
        Currently, method 1 is available only in the Chinese mainland.
        
    -   Method 2: In the **Terminal** pane, switch to the module (**entry** module in this example) to which you want to import the shared package, and run the following command to install the shared package. DevEco Studio will automatically add the package as a dependency to the **oh-package.json5** file of the module.
        
        cd path/to/your/project/entry
        ohpm install @ohos/lottie
        
    -   Method 3: Set the shared package as a dependency in the **oh-package.json5** file of the module to which you want to import the shared package. The following is an example configuration:
        
        "dependencies": {
          "@ohos/lottie": "^2.0.0"
        }
        
        After the dependency is set, run the **ohpm install** command to install it to the **oh\_modules** folder of the module directory.
        
        ohpm install
        
    
-   To reference the source code of a local module (which must belong to the same project as the host module), for example, if the **entry** module needs to depend on the source code of the **foo** module, there are the following two methods:
    -   Method 1: In the **Terminal** pane, switch to the target module (**entry** module in this example), and run the following command to install the shared package. The package will be automatically added as a dependency to the **oh-package.json5** file of the module.
        
        cd path/to/your/project/entry
        ohpm install path/to/foo
        
    -   Method 2: Set the shared package as a dependency in the **oh-package.json5** file of the target module, that is, the **oh-package.json5** file of the **entry** module in this example. The following is an example configuration:
        
        "dependencies": {
          "foo": "file:path/to/foo"  // The path can also be a relative path starting from the directory where oh-package.json5 is located.
        }
        
        After the dependency is set, run the **ohpm install** command to install it. The source code of the **foo** module is installed in the **oh\_modules** directory of the **entry** module.
        
        ohpm install
        

-   To reference a shared package from a local HAR or HSP file, use either of the following methods:
    -   Method 1: In the **Terminal** pane, switch to the module (**entry** module in this example) to which you want to import the shared package, and run the following command to install the shared package. The package will be automatically added as a dependency to the **oh-package.json5** file. In the following example, the HAR or HSP file is in the root directory of the project:
        -   Referencing a HAR:
            
            cd path/to/your/project/entry
            ohpm install path/to/package.har
            
        -   Referencing an HSP (the \*.tgz file is generated by [building](../developing-and-publishing-shared-packages/developing-a-dynamic-shared-package/document.md#section67683213597) the HSP in release mode):
            
            cd path/to/your/project/entry
            ohpm install path/to/package.tgz
            
    -   Method 2: Set the shared package as a dependency in the **oh-package.json5** file of the module to which you want to import the shared package. In the following example, the HAR or HSP file is in the root directory of the project:
        
        -   Referencing a HAR:
            
            "dependencies": {
              "package": "file:path/to/package.har" // The path can also be a relative path starting from the directory where oh-package.json5 is located.
            }                                       
            
            ![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/b3/v3/i_ahaT57SvK_GeJuQIvyAg/note_3.0-en-us.png?HW-CC-KV=V1&amp;HW-CC-Date=20260410T062136Z&amp;HW-CC-Expire=86400&amp;HW-CC-Sign=F5163BE1253AE440045CDA7D0A5265372ECA19A08F31F089320D747C002F936B)
            
            In the code snippet, **package.har** indicates the file name of the third-party package. **package** indicates the dependency name used to reference this third-party package. You are advised to keep it consistent with the name of the third-party package, that is, the **name** field in the **oh-package.json5** file of the third-party package.
            
        
        -   Referencing an HSP:
            
            "dependencies": {
              "package": "file:path/to/package.tgz" // The path can also be a relative path starting from the directory where oh-package.json5 is located.
            }
            
        
        After the dependency is set, run the **ohpm install** command to install it to the **oh\_modules** directory of the module.
        
        ohpm install
        

When installing or uninstalling a shared package, you can add hooks to the **oh-package.json5** file of the project or target module to manage the lifecycle of the **install** and **uninstall** commands. The following is an example:

 "hooks": {
    "preInstall": "echo 00 preInstall", // Before the install command is executed
    "postInstall": "echo 00 postInstall", // After the install command is executed
    "preUninstall": "echo 00 preUninstall", // Before the uninstall command is executed
    "postUninstall": "echo 00 postUninstall"  // After the uninstall command is executed
  }

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/38/v3/3vkt2mwSTL6zIYZxcHJ9pg/note_3.0-en-us.png?HW-CC-KV=V1&amp;HW-CC-Date=20260410T062136Z&amp;HW-CC-Expire=86400&amp;HW-CC-Sign=6E083D6BC40EE7E491F9636DBD30B1CE3719233B1988E2D31BB493866ACA34A2)

-   Currently, hooks in the **oh-package.json5** file of the project or target module can be executed, but hooks in dependencies cannot.
-   Only the dependencies declared in **dependencies** of the **oh-package.json5** file in the module or project directories are processed as dependencies during compilation and build.

#### Using OHPM Index to Manage Third-Party Packages

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/17/v3/4IOEvUFiQFO3s1KxHdoJhw/note_3.0-en-us.png?HW-CC-KV=V1&amp;HW-CC-Date=20260410T062136Z&amp;HW-CC-Expire=86400&amp;HW-CC-Sign=B93823F12741DA983621C56358C4DB7D132973E896A39D50C8698F04A2704BD7)

Currently, this feature is available only in the Chinese mainland.

Since DevEco Studio 6.0.0 Beta5, you can access the OHPM Index for efficient filtering and management of the OHPM open-source central repository. It streamlines your package selection, reduces risks caused by information asymmetry, and helps you quickly find and integrate the required open-source shared packages.

1.  On the menu bar, choose **Tools** > **OHPM Index**.
    
2.  In the left search box, you can search for a shared package by name. Alternatively, browse the directory tree by category to view recommended dependencies. Once you have selected the desired shared package, click the blue **Install** button in the upper-right corner to install it.
    
3.  If a popup appears during installation, click the **Add** button. This adds the OpenHarmony central repository address to your **.ohpmrc** file.
    
4.  After the shared package is installed successfully, you can find its name and version information in your project-level **oh-package.json5** file. The package will also be added to your **oh\_modules** directory.
5.  Click ![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/db/v3/-8eGmMIgR1u-YI4BSPHnog/en-us_image_0000002532669999.png?HW-CC-KV=V1&amp;HW-CC-Date=20260410T062136Z&amp;HW-CC-Expire=86400&amp;HW-CC-Sign=888F5773A7CF1B085587FB5F5392405817D926ED2CAB497FCF61BBC9034804FE "Click to enlarge") in the upper-left corner of the page to view a list of currently installed shared packages. If a package is not the latest version, you can click the **Update** button to update it, or click the **Delete** button to remove it.
    
6.  If there are recommended alternative shared packages for the dependencies you are currently using, you can click the yellow bulb icon in the editor. In the displayed dialog, choose **Replace selected with recommended library** to swap the current dependency for the recommended one, or **Replace all with recommended libraries** to replace all similar dependencies in the current file at once.
