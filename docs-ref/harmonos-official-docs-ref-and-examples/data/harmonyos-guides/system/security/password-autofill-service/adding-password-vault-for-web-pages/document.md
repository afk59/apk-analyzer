#### Storage Specifications of Web Page Passwords

1\. After the password form is successfully submitted, ArkWeb triggers page redirection to another page to trigger password saving.

2\. When using ArkWeb to implement HTML5 login in a native application, do not destroy the ArkWeb instance immediately after successful login. Otherwise, the system will not be able to prompt users to save the password.

#### Specifications of the Web Page Password Form

ArkWeb uses the Chromium intelligent algorithm to automatically identify user names and passwords on web pages. The algorithm has certain restrictions on the design of the user name and password form.

## Recommended Password Login Form

1.  Use static login pages or login form elements instead of dynamically inserting form elements such as **<form>** and **<input>** to pages using JS scripts.
2.  Use the **<input>** element to implement the user name and password text boxes and integrate them into the same **<form>** element. By default, the user name and password text boxes are editable, and the login scenario has exactly one **<input>** element whose type is **"password"**.
3.  Logins are triggered by buttons, and a successful login should bring up a new page.
4.  The username box carries the **autocomplete="username"** and **id** or **name** attributes, and the following recommended values are used, which facilitates the algorithm to infer the username element.

## Password Login Form Types That Do Not Support Automatic Filling

1.  The initial page does not contain the user name and password form element. After the login page is displayed, a user name and password form of the non-**<form>** type is added.
2.  The password text box carries the **autocomplete="new-password"** attribute.
3.  The user name and verification code text boxes carry the **type="number"** attribute. No password text box is provided.
4.  There is an **<input>** element between the user name and password text boxes. As a result, the user name element inferred by the algorithm does not meet the user expectation.
5.  The focused state or value of the **<input>** element is changed on the web page using a javascript script.
6.  The following password type identifiers are matched in the **id**, **name**, and **label** of the user name **<input>** element:
