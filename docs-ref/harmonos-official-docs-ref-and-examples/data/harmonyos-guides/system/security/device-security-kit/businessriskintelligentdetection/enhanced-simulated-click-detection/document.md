# Enhanced Simulated Click Detection

#### Use Cases

Starting from version 6.0.2(22), enhanced simulated click detection is supported.

An app calls the **detectSimulatedClickRiskEnhanced** API of Device Security Kit to obtain the enhanced simulated click detection result for detecting cheating behaviors like automated clicks and device farming.

The app can evaluate how to perform service operations based on the detection result.

#### Restrictions

Each app can call the API for up to 10 times every 30 seconds and up to 20 times per day on each device.

#### Service Process

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/c8/v3/XXHJy5QmS1-UKGiM-wDtiw/en-us_image_0000002482863616.png?HW-CC-KV=V1&amp;HW-CC-Date=20260410T062008Z&amp;HW-CC-Expire=86400&amp;HW-CC-Sign=14491067EFD6997312A9B6EAC0BF1F764843C099523BA24EEA50E0F6541347AA)

The process is as follows:

1.  Your app obtains the nonce value.
    
    When calling the **detectSimulatedClickRiskEnhanced** API, you must pass a randomly generated nonce value, which will be contained in the detection result. You can check the nonce value to verify that the returned result corresponds to your request and does not encounter replay attacks.
    
    ![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/93/v3/KhUaEmRaRBmQ30CHThnU5w/note_3.0-en-us.png?HW-CC-KV=V1&amp;HW-CC-Date=20260410T062008Z&amp;HW-CC-Expire=86400&amp;HW-CC-Sign=43449AF07187C5549B2B7A0FF17D0EA3A9ED611F87148B4B2E8AEEDF01B01DEE)
    
    -   A nonce value must contain 24 to 80 bytes.
    -   It is recommended that a new nonce value be randomly generated by the app server for each request.
    
2.  Your app calls the **detectSimulatedClickRiskEnhanced** API to initiate an enhanced simulated click detection request.
    
    After receiving the request, Device Security Kit collects the simulated click clue data of the current device, sends the clue data and nonce value to the Device Security server for detection, and passes the detection result to your app through the return value of the **detectSimulatedClickRiskEnhanced** API.
    
3.  When your app initiates a service request, your app server verifies the integrity of the enhanced simulated click detection result.

#### Development Procedure

1.  Import the Device Security Kit module and related public modules.
    
    import { businessRiskIntelligentDetection } from '@kit.DeviceSecurityKit';
    import { BusinessError } from '@kit.BasicServicesKit';
    import { hilog } from '@kit.PerformanceAnalysisKit';
    import { cryptoFramework } from '@kit.CryptoArchitectureKit'
    
2.  Call the **detectSimulatedClickRiskEnhanced** API to obtain the enhanced simulated click detection result.
    
    const TAG = "BusinessRiskIntelligentDetectionJsTest";
    
    let nonceLength = 48;
    let nonceBlob = cryptoFramework.createRandom().generateRandomSync(nonceLength);
    let params = {
        version: 1,
        nonce: nonceBlob.data,
        algorithm: businessRiskIntelligentDetection.SigningAlgorithm.ES256
    } as businessRiskIntelligentDetection.SimulatedClickDetectionEnhancedRequest;
    try {
        hilog.info(0x0000, TAG, 'Detect simulated click risk enhanced begin.');
        businessRiskIntelligentDetection.detectSimulatedClickRiskEnhanced(params).then((result: string) => {
            hilog.info(0x0000, TAG, 'Detect simulated click risk enhanced success: %{public}s', result);
        }).catch((error: Error) => {
            let e: BusinessError = error as BusinessError;
            hilog.error(0x0000, TAG, 'Detect simulated click risk enhanced failed: %{public}d %{public}s', e.code, e.message);
        });
    } catch (error) {
        let e: BusinessError = error as BusinessError;
        hilog.error(0x0000, TAG, 'Detect simulated click risk enhanced failed: %{public}d %{public}s', e.code, e.message);
    }
    
3.  Verify the enhanced simulated click detection result on your app server.
    
    The result returned by the enhanced simulated click detection API is a JWS string. To verify the detection result, perform the following steps (for a complete example, see the [Java sample code](https://gitcode.com/HarmonyOS_Samples/device-security-kit-sample-code-business-risk-intelligent-detection-server-demo-java/blob/master/readme_en.md)):
    
    1.  Parse the JWS string to obtain **header**, **payload**, and **signature**.
    2.  Obtain the certificate chain from **header** and use the [Huawei CBG Device Attestation Root CA](https://pki.consumer.huawei.com/ca/cer/Huawei_CBG_ECC_Device_Attestation_Root_CA.cer) certificate to verify it.
    3.  Check whether **Common Name** of the x5c\[0\] certificate in the certificate chain is **Harmony OS Device Attestation Service**.
    4.  Obtain the signature from **signature** and verify it.
    5.  Obtain the enhanced simulated click detection result from **payload**. The format and example are as follows:
        
        {
            "timestampMs": 9860437986543,
            "version": 1,
            "riskDecision": "fake",
            "tags": \["AbnormalTap"\]
        }
        
        ![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/29/v3/FLfWQKnITjK1KLe_daVfxQ/note_3.0-en-us.png?HW-CC-KV=V1&amp;HW-CC-Date=20260410T062008Z&amp;HW-CC-Expire=86400&amp;HW-CC-Sign=CE1D24A76602C1BF780FBEB1487D419E3FE95386288D17618757691B8F82788D)
        
        For details about the parameters, please refer to the parameter description of [detectSimulatedClickRiskEnhanced](https://developer.huawei.com/consumer/en/doc/harmonyos-references/devicesecurity-brid-api#section666116174014).
