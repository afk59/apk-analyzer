# System Integrity Check

#### Use Cases

An app calls the **checkSysIntegrity** API of Device Security Kit to obtain the system integrity check result and determine whether the device environment is secure, for example, whether the device environment has been jailbroken or the device is a non-real device.

An app can warn users of security risks, prompt users to exercise caution when performing service operations, or block operations as needed based on check results.

#### Restrictions

-   The system integrity check capability is supported on phones, tablets, and PCs/2-in-1 devices. Starting from version 5.1.0(18), it's also supported on wearables.
-   Each app can call the API for up to 10,000 times per day and five times per minute on each device. A maximum of five concurrent calls are supported on each device.

#### Service Process

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/73/v3/_T9hVEbNRaGYizX7HXqZgQ/en-us_image_0000002482908428.png?HW-CC-KV=V1&amp;HW-CC-Date=20260410T062006Z&amp;HW-CC-Expire=86400&amp;HW-CC-Sign=43162FB22E867EDE6F6D3D023AADB0B21572E82CE53601B2E4D1FC953EC14A35 "Click to enlarge")

The process is as follows:

1\. **Your app obtains the nonce value.**

When calling the **checkSysIntegrity** API, you must pass a randomly generated nonce value, which will be contained in the check result. You can check the nonce value to verify that the returned result corresponds to your request and does not encounter replay attacks.

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/9c/v3/-9ZCXTeuQ26KYRFcMJwBzA/note_3.0-en-us.png?HW-CC-KV=V1&amp;HW-CC-Date=20260410T062006Z&amp;HW-CC-Expire=86400&amp;HW-CC-Sign=C5EA1CDC0B2E35A65503D250CE6B0C0CBFDF7A2BB882BE2245563D13CD414ED4)

-   A nonce value must contain 16 to 66 bytes and be encoded using Base64.
-   It is recommended that a new nonce value be randomly generated by the server for each request.

2\. **Your app calls the checkSysIntegrity API to send a system integrity check request.**

After receiving the request, Device Security Kit collects the system integrity check data, sends the check data and nonce value to the Device Security server for verification, and returns the check result to your app through the **checkSysIntegrity** API.

3\. **When your app initiates a service request, your app server verifies the check result of the checkSysIntegrity API.**

If the check result is **false**, you need to check the risk type in **detail** and determine whether to notify the user based on the risk type and your app's security requirements.

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/0/v3/5mAHpqTITQywJyHf7o-foA/note_3.0-en-us.png?HW-CC-KV=V1&amp;HW-CC-Date=20260410T062006Z&amp;HW-CC-Expire=86400&amp;HW-CC-Sign=CDB2167A941439DD386DBE5AC91415272FBF8E8FF0645784E831DD9D4AEE9D4E)

-   The current solution has combined the server and client to mitigate security risks. However, the **checkSysIntegrity** API cannot mitigate all security risks.
-   The system integrity check result can be used as one of the system security proofs. You should consider relevant risks caused by possibly incorrect check results and the impacts to users. You are advised not to use the check result as the only proof to determine whether the current device is secure. It's better to take extra measures to further reduce risks.
-   To improve user experience when notifying users within the app, consider using friendly messages like:
    
    Your device might be at risk or running in an insecure environment. Please exercise caution when using the _XXX_ feature.
    

#### API Description

The following table lists the system integrity check API, which is an ArkTS API. For more information about the API, please refer to [API Reference](https://developer.huawei.com/consumer/en/doc/harmonyos-references/devicesecurity-arktsapi).

| 
API

 | 

Description

 |
| :-- | :-- |
| 

checkSysIntegrity(req: SysIntegrityRequest): Promise<SysIntegrityResponse>

 | 

Checks system integrity.

 |

#### Development Procedure

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/e4/v3/oOJgia93QUSuwpyz0m_KuA/note_3.0-en-us.png?HW-CC-KV=V1&amp;HW-CC-Date=20260410T062006Z&amp;HW-CC-Expire=86400&amp;HW-CC-Sign=98B51FD475C52D003DCDB4259D2171956957FB3B6D2B87D22A45ED1EA20C6086)

Ensure that you have [enabled SafetyDetect](../../preparations/enabling-device-security-kit/document.md) and [requested the profile](https://developer.huawei.com/consumer/en/doc/app/agc-help-profile-0000002270709473).

1.  Import the Device Security Kit module and related public modules.
    
    import { safetyDetect } from '@kit.DeviceSecurityKit';
    import { BusinessError } from '@ohos.base';
    import { hilog } from '@kit.PerformanceAnalysisKit';
    
2.  Call the API to obtain the system integrity check result.
    
    ![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/8c/v3/HYhte6A4Rmi70N1bto2Fsw/caution_3.0-en-us.png?HW-CC-KV=V1&amp;HW-CC-Date=20260410T062006Z&amp;HW-CC-Expire=86400&amp;HW-CC-Sign=E89D6750156F5D14D9BAAD0BD07309E0F102F33EBB0CE52B663357FC15727815)
    
    This API involves device-cloud synergy and time-consuming operations such as network connection. Therefore, do not execute this API in the UI thread, in order to avoid UI thread blocking.
    
    const TAG = "SafetyDetectJsTest";
    
    // Request system integrity check and process the result.
    let req : safetyDetect.SysIntegrityRequest = {
      nonce : 'imEe1PCRcjGkBCAhOCh6ImADztOZ8ygxlWRs' // Random nonce value generated by the server.
    };
    try {
      hilog.info(0x0000, TAG, 'CheckSysIntegrity begin.');
      const data: safetyDetect.SysIntegrityResponse = await safetyDetect.checkSysIntegrity(req);
      hilog.info(0x0000, TAG, 'Succeeded in checkSysIntegrity: %{public}s', data.result);
    } catch (err) {
      let e: BusinessError = err as BusinessError;
      hilog.error(0x0000, TAG, 'CheckSysIntegrity failed: %{public}d %{public}s', e.code, e.message);
    }
    
3.  Verify the check result on your app server.
    
    The check result is a JSON Web Signature (JWS) string, which consists of the following parts:
    
    -   Header
    -   Payload
    -   Signature
    
    The three parts are encoded using Base64URL and concatenated through dots (.). You can obtain the signature by concatenating the header and payload and then signing the concatenated string using the algorithm specified in the header.
    
    **Example**
    
    eyAgICAiYW\*\*.\*\*.\*Jxse
    eyAgICAiYW\*\*.\*\*.\*JodHxx
    
    For more about JWS, please refer to [JSON Web Signature](https://www.rfc-editor.org/rfc/rfc7515.html).
    
    Fields in JWS-format **Header** are as follows:
    
    {
        "alg": "ES256",
        "typ":"JWS",
        "x5c": \["","",""\]
    }
    
    ![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/47/v3/ajAADtqhT5WAxxtS57aUpg/note_3.0-en-us.png?HW-CC-KV=V1&amp;HW-CC-Date=20260410T062006Z&amp;HW-CC-Expire=86400&amp;HW-CC-Sign=A7D2A93F4E83B64AB703351F8A2EC9750116300732F4FB66EFDEC2AA408B530D)
    
    **alg**: signature algorithm name. The value **ES256** indicates that ECDSA is used for signature.
    
    **typ**: The value is always **JWS**.
    
    **x5c**: certificate chain used by the Device Security server for JWS signing. The certificate chain contains three levels of certificates: **x5c\[0\]** indicates the certificate for JWS signing, **x5c\[1\]** indicates the level-2 CA certificate of a Huawei device, and **x5c\[2\]** indicates the root CA certificate of a Huawei device.
    
    Fields in JWS-format **Payload** are as follows:
    
    {
      "hapCertificateSha256": "xxx",
      "hapBundleName": "xxx",
      "appId": "xxx",
      "basicIntegrity": false,
      "detail": \[
        "attack",
        "jailbreak",
        "emulator"
      \],
      "nonce": "xxx",
      "timestamp": 1604098577327
    }
    
    ![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/ec/v3/l7IWne6nTJaREodrRwTbew/note_3.0-en-us.png?HW-CC-KV=V1&amp;HW-CC-Date=20260410T062006Z&amp;HW-CC-Expire=86400&amp;HW-CC-Sign=906AD7C828AEFA1485E572BDAD6BB15F6BDC40AA39C93A16D1859CB7DA590396)
    
    **nonce**: nonce character string passed when the **checkSysIntegrity** API is called.
    
    **timestamp**: timestamp generated by the server.
    
    **hapBundleName**: your app package name.
    
    **hapCertificateSha256**: SHA-256 digest of your app's signing certificate.
    
    **basicIntegrity**: system integrity check result. The value **true** indicates that the system is integral, and the value **false** indicates there are risks.
    
    **appId**: ID of your app.
    
    **detail**: optional field. When the value of **basicIntegrity** is **false**, this field provides the cause of the risk. You can make decisions accordingly based on the risk. The options are as follows:
    
    -   **jailbreak**: indicates that the device is jailbroken.
    -   **emulator**: indicates that the device is a non-real device.
    -   **attack**: indicates that the device is attacked.
    
    To verify the check result, perform the following steps:
    
    1.  Parse the JWS string to obtain **header**, **payload**, and **signature**.
    2.  Obtain the certificate chain from **header** and use the [Huawei CBG Root CA G2](https://h5hosting-drcn.dbankcdn.cn/cch5/crl/pki_CA_RootG2Ca/RootG2Ca.cer) certificate to verify it.
    3.  Verify that the certificate chain contains three levels of certificates and the domain name of the **x5c\[0\]** certificate is **sysintegrity.platform.hicloud.com**.
    4.  Obtain the signature from **signature** and verify it.
    5.  Obtain the integrity check result from **payload**. If the value of **basicIntegrity** in the check result is **false**, the **detail** field provides the reason why the result is false. You can determine whether to notify the user based on your security requirements.
    
    We've provided the [server sample code (Java)](https://gitcode.com/HarmonyOS_Samples/device-security-kit-samplecode-safetydetect-serverdemo-java) for verifying the signature of the system integrity check result for your reference.
    
    ![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/f6/v3/une1ty8UQtWWMe9V5qsslg/caution_3.0-en-us.png?HW-CC-KV=V1&amp;HW-CC-Date=20260410T062006Z&amp;HW-CC-Expire=86400&amp;HW-CC-Sign=E9A94255B79F7A765FE8AA5679CC1598CF67E2DCC7B1B89F463CCE690AD9B421)
    
    Verify the certificates and signature as instructed in the preceding steps to ensure the integrity of the check result and prevent tampering.
